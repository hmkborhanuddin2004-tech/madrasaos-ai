# MadrasaOS AI - Granular User Roles & Permissions Matrix

## Role Hierarchies and Scopes

```
Level 0: Super Admin (Platform Operator / Multi-Tenant SaaS Admin)
Level 1: Madrasa Admin / Muhtamim (Institution Owner / Full Tenant Access)
Level 2: Branch Manager / Nayeb-e-Muhtamim (Campus Level Operations)
Level 3: Functional Officers
         ├── Principal / Academic Head (Nazim-e-Ta'leemat)
         ├── Accountant / Bursar (Nazim-e-Maliyat)
         ├── Hostel Manager / Warden (Nazim-e-Darul Iqamah)
         └── Librarian (Kutubkhana In-charge)
Level 4: Instructional Staff
         ├── Senior Kitab Teacher (Ustad)
         └── Hifz Teacher (Hafiz / Muallim)
Level 5: End Users / Beneficiaries
         ├── Guardian (Wali / Abhibhabok)
         └── Student (Talib-e-Ilm)
```

## Attribute-Based Access Control (ABAC) Rules

1. **Teacher Scope Limitation**:
   - `Teacher.canViewStudent(student)` is TRUE if and only if `student.class_id IN (teacher.assigned_classes)`.
   - `Teacher.canEnterMarks(subject_id)` is TRUE if and only if `subject.teacher_id == current_user.teacher_id`.
2. **Guardian Privacy Boundary**:
   - A guardian's authentication token embeds verified child IDs (`student_guardians.student_id`).
   - Querying any student outside the guardian's verified roster immediately returns `403 Forbidden` with a security audit event logged.
3. **Accountant Academic Separation**:
   - Accountants have zero access to enter or modify examination marks, Hifz Sabaq ratings, or academic progression decisions.
4. **Human Approval Safeguards for Automations & AI**:
   - Mass guardian notifications (>10 recipients) require an explicit dual-step approval from either `Madrasa Admin` or `Principal`.
   - Financial adjustments or fee waivers generated by automation nodes require an `Accountant` or `Madrasa Admin` digital signature.
